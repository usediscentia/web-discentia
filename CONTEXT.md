# Discentia — Domain Glossary

Terms used throughout this codebase. Use these names in issues, refactor proposals, test names, and commit messages. Don't drift to synonyms.

---

## Core domain concepts

**Library** — a named collection of content the user wants to study. Has a color, optional description, and an item count. Users can create multiple libraries for different subjects.

**LibraryItem** — a single piece of content inside a Library. Types: `text`, `markdown`, `image`, `pdf`, `file`. Stores raw content, a preview, optional `rawFile` blob, and `metadata` (including `chunks` for PDFs).

**Chunk** — a segment of a LibraryItem's content, used for context injection into AI prompts and for citations. PDFs are split into chunks by `pdf-chunker.ts` using heading detection and block merging. Not a fixed-size split.

**Conversation** — a chat session linked to zero or more Libraries via `libraryIds`. Contains a sequence of Messages.

**Message** — a single turn in a Conversation (role: `user` | `assistant`). May carry `citations`, `attachments`, and an optional `exerciseId` when the assistant generated an exercise.

**Citation** — a reference from an assistant Message back to a specific LibraryItem (and optionally a Chunk). Scored by word-overlap in `citations.ts`. Only items in `allowedItemIds` (the injected context) can be cited.

**Exercise** — a structured learning object generated by the AI. Has a `type` (`flashcard` | `quiz` | `sprint` | `connections` | `fillgap` | `bossfight`) and a `data` payload specific to that type. Linked to a `messageId` and optionally a `sourceItemId`. Accumulates `results` over time.

**ExerciseType** — singular string discriminating the exercise variant: `"flashcard"`, `"quiz"`, `"sprint"`, `"connections"`, `"fillgap"`, `"bossfight"`, `"crossword"`. Crossword falls through to "coming soon" in the renderer.

**SRSCard** — a flashcard scheduled for spaced repetition. Carries SM-2 fields: `easeFactor`, `interval`, `repetitions`, `nextReviewDate`, `lastReviewDate`, `lapses`. Optionally linked to a LibraryItem via `libraryItemId`.

**ActivityEvent** — a timestamped log entry for user actions. Types currently in use: `srs_review`, `exercise_completed`. Powers streak and heatmap in Stats.

**Study session** — the active state when the user is reviewing SRS cards. Managed by `study.store.ts`. Exposes the current card, answer state, hint ladder, and AI evaluation result.

**Evaluation** — the AI's verdict on a study answer. Returns `verdict` (`correct` | `partial` | `incorrect`) and optional `keyMissing`. Produced inline in `study.store.ts`; candidate for extraction to `services/ai/evaluation.ts`.

## Architecture concepts (from LANGUAGE.md)

**StorageService** — the single module through which all UI code accesses Dexie/IndexedDB. Rule: no component or hook calls `getDB()` directly. All reads and writes go through `StorageService`. Defined in `src/services/storage/index.ts`.

**Provider adapter** — a concrete implementation of the `AIServiceProvider` interface for one AI backend (OpenAI, Anthropic, Ollama, OpenRouter, GitHub Copilot, LM Studio). Providers are interchangeable behind the interface; the UI never imports a provider directly.

**Generation modal** — the multi-step flow (Configure → Generating → Review → Schedule → Success) for generating exercises from a LibraryItem. State machine in `generation.store.ts`. The modal is a singleton lifted into `AppShell`.

**Exercise type seam** — the `PROMPT_BUILDERS` map in `exercise.prompts.ts` keyed on `ExerciseType`. All prompt routing for exercise generation goes through this map. **Wired as of commit `1c4b839`**: `ConfigureStep` now exposes a type selector and `GenerationModal` routes through `buildExercisePrompt(type, …)`.

**SSE streaming loop** — the identical read-buffer / split-on-newline / `[DONE]` / abort / releaseLock pattern duplicated across 4 fetch-based providers (OpenAI, OpenRouter, LM Studio, GitHub Copilot). Candidate for extraction to `src/services/ai/stream.ts`.

## Avoid these synonyms

| Don't say | Say instead |
|-----------|-------------|
| document | LibraryItem |
| deck | Library |
| flashcard set | Exercise (type: flashcard) |
| card | SRSCard (when talking about SRS scheduling) or flashcard card (when talking about exercise data) |
| service | StorageService (specific) or Provider adapter (AI-specific) |
| backend | there is no backend — say "Dexie" or "IndexedDB" or "AI provider" |
